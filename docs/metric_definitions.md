CHANGE LOG

A.BUSINESS CONTEXT:

1. WHO USES THIS ANALYSIS? : This dataset is of an online Merchandise Store. Therefore, this analysis will be mostly helpful to the sales team, product team, marketing team and the finance team.

2. WHAT DECISION DOES IT SUPPORT? : The summaries drawn from this analysis will help the various departments change or improve their strategies and approach with which they make decisions to improve efficiency.

B.DATA SCOPE :

SOURCE : The dataset used for this project has been taken from Google Analytics sample dataset on BigQuery, from the Google Merchandise Store.

PERIOD :

WHAT ONE ROW MEANS:
-> SESSIONS : This means one row per user visit to the website.
-> EVENTS : This means one row per individual user interaction or action tracked during a visit.
-> ORDERS : This means one row per completed commercial transaction or purchase.

C.USERS AND COHORTS :
->USER: A unique identifier assigned to a specific browser instance, represented by the 'fullVisitorId' field.
● Limitation: The 'fullVisitorId' identifies a specific browser cookie rather than an actual person, meaning a single individual using two seperate devices or browsers will be counted as two distinct users.

->NEW USER: A visitor whose first recorded session in the dataset has a 'visitNumber' equal to 1.
● Cohort & Retention Rule: If a user's first observed record has a 'visitNumber' > 1, they interacted with the platform prior to the dataset's start date, making their actual first visit date unknown. These users should be retained in the overall dataset but strictly excluded from cohort and retention analyses.

->COHORT: The calendar month of a user's first observed session (visitNumber = 1). Using monthly cohorts provides a cleaner, more readable trends analysis than weekly cohorts for a one-year dataset.

D.LEVEL AND SEQUENCE RULE: Session-based-
Each visit is evaluated independently since shopping actions occur within individual sessions.

->FUNNEL STAGES:

1. Product View
2. Add to Cart
3. Checkout
4. Purchase

->FORMULAS & METRICS:
● Stage Conversion Rate: Sessions that reach a target stage divided by sessions that reached the preceding stage, multiplied by 100.

● Drop-off Rate: 100 minus the stage conversion rate.

● Overall Conversion Base & Formula: The base is restricted to sessions that viewed a product (rather than all sessions), calculated as sessions with a purchase divided by sessions with a product view, multiplied by 100.

● Data Limitation Note: Because real-world tracking data frequently features out-of-order or missing intermediate events, we will separately measure and report the volume of purchases that occur without a recorded preceding step as a data quality limitation.

E.RETENTION :
->RETURN DEFINITION: A visit qualifies as a return if it is any later session that is not a bounce (where a bounce is defined as a visit consisting of a single page view with no user interaction).

->DAY-N CONVENTION:
● Day 0: The exact calendar day of the user's first observed session.
● Exact Day-N Retention: A user has a qualifying return session on exactly N days after Day 0.
● Within Day-N Retention: A user has at least one qualifying return session within the N-day window following Day 0.

->ELIGIBILITY RULE: A visitor is eligible for Day N retention analysis only if their Day 0 date plus N days falls on or before the final date of the dataset.

->FORMULA: Day-N retention = visitors in the cohort with a qualifying return on day N ÷ eligible visitors in the cohort × 100.

F.REVENUE AND ORDERS :
● ORDER: One unique transaction is identified by a distinct 'transactionId'.
● REVENUE: Total order revenue divided by 1,000,000 (since raw values are stored in millionths of the currency unit, assumed to be US Dollars).
● AVERAGE ORDER VALUE (AOV): Total revenue divided by the total number of orders
● REVENUE PER ACQUIRED USER: Total revenue generated by a cohort's users divided by the total number of users in the cohort
● REPEAT PURCHASE RATE: The number of buyers with more than one order divided by all the buyers, within the data period
● CUSTOMER LIFETIME VALUE (LTV) NOTE: It is not calculated because the one-year data period is too short to observe true long-term value, and an accurate LTV model requires additional structural assumptions regarding customer lifespan and churn.

G.KNOWN LIMITATIONS :
● Cookie IDs Are Not People: The fullVisitorId identifies a browser cookie rather than an individual person, meaning user counts are distorted whenever a single user switches devices, clears cookies, or uses multiple browsers.

● No True Signup Date: User acquisition relies on the first observed session in the dataset rather than a verified account registration date, making historical user classification dependent on the dataset's observation window.

● Limited Scope: Insights and behavioral patterns are derived from a single e-commerce store across a one-year timeframe, restricting the generalizability of findings to other industries or broader time horizons.

● Tracking Gaps & Bot Activity: Automated traffic, ad blockers, non-standard user browsers, or analytics script failures can introduce noise or obscure true user behavior.

● Incomplete Funnel Sequences: Events within a session may be missed or dropped by tracking implementation, leading to recorded purchases that lack preceding product views or add-to-cart events.
